# 🧪 Self-Logic-Lab-Boot

**基于 Spring Boot 3 & Java 17，记录那些杂七乱八但有用的逻辑碎片。**


---

## 🏗️ 核心架构：三层数据流转协议

本项目采用严谨的三层模型，确保数据在不同层级间的高效、安全流转：

### 1. BaseResult - 统一响应契约
所有 RESTful 接口的终点。
- **作用**: 规范 JSON 结构，包含 `code`, `msg`, `data` 三大核心字段。
- **价值**: 降低前后端对接成本，确保全局异常响应与正常响应结构完全对齐。

### 2. ServiceResult<T> - 业务逻辑载体
Service 层与 Controller 层的核心通信协议。
- **特性**:
    - 通过 `isSuccess()` 快速进行逻辑分支判断，无需比对状态码。
    - 采用静态工厂方法模式 (如 `success()`, `failure()`)，提升代码逻辑表达力。
- **价值**: 彻底解耦业务状态与 HTTP 状态码，使 Service 层代码具备更强的可移植性和纯粹性。

### 3. ServicePageDataResult<T> - 分页数据容器
专为复杂查询与大批量数据展示设计。
- **特性**: 严格封装 `total` (总条数) 与 `dataList` (结果集)。
- **价值**: 解决了分页场景下多余字段传递的混乱，为前端组件提供标准、预期的分页数据格式。

> #### 💡 架构总结：全栈通用的数据契约
> **项目深度复用此套数据格式，构建了从数据库到前端的“无损通信隧道”：**
> * **标准契约**：前端解析逻辑只需对接一套 `BaseResult` 结构，实现一次封装，处处调用。
> * **逻辑闭环**：`ServiceResult` 承载业务语义，`BaseResult` 承载协议语义，两者配合实现“逻辑防腐”，新模块可零成本接入此套体系。
> * **分页标准**：通过 `ServicePageDataResult` 沉淀了标准分页元数据格式，极大提升前后端联调效率。

## 🛠️ 分页请求核心逻辑：BaseLimitRequest

项目针对分页场景开发了 **“双模自动转换”** 机制，这是对传统分页逻辑的一次优雅下沉：

- **自动逻辑转换**:
  覆写 `getPageNumber()` 方法。该方法自动返回(SQL Offset)。实现了从“用户页码”到“数据库偏移量”的透明转换。
- **精准分组校验**:
  利用 `jakarta.validation` 的分组特性，同一 DTO 支持两套校验规则：
    - `@Validated(PageGroup.class)`：专注于页码模式校验。
    - `@Validated(OffsetGroup.class)`：专注于下标模式校验。
